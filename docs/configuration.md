# Configuration reference

Every knob that affects how SentryDemo runs — backend env vars, Android
properties, build flags, and the ports/volumes they touch.

## Backend — `sentry-selfhost/.env`

Lives at `sentry-selfhost/.env`. Copy from `.env.example` and edit. `setup.sh`
appends this file onto upstream's `.env`, so our values override upstream
defaults (last-write-wins in dotenv parsing).

### Networking

| Key | Default | Purpose |
| --- | --- | --- |
| `SENTRY_BIND` | `9000` | Host port `nginx` binds to. Accepts `port` or `ip:port` (e.g. `127.0.0.1:9000` for loopback-only). |
| `COMPOSE_PROJECT_NAME` | `sentry-self-hosted` | Docker compose project name prefix. Defined in upstream `.env`; don't override unless you understand the implications for volume naming. |
| `COMPOSE_PROFILES` | `feature-complete` | `feature-complete` enables everything; `errors-only` strips perf/replays/profiles for a lighter footprint. |

### Retention

| Key | Default | Purpose |
| --- | --- | --- |
| `SENTRY_EVENT_RETENTION_DAYS` | `30` | Days of event/transaction history kept. `cron` service prunes older events nightly. |

### Email / SMTP

Leave unset for local demo (the bundled `smtp` service catches everything and
swallows it). Set these for production-like notifications.

| Key | Example | Purpose |
| --- | --- | --- |
| `SENTRY_EMAIL_HOST` | `smtp.sendgrid.net` | SMTP relay host |
| `SENTRY_EMAIL_PORT` | `587` | SMTP port (587 for STARTTLS, 465 for SMTPS) |
| `SENTRY_EMAIL_USER` | `apikey` | SMTP username (for SendGrid: literally `apikey`) |
| `SENTRY_EMAIL_PASSWORD` | `<token>` | SMTP password |
| `SENTRY_EMAIL_USE_TLS` | `true` | Enable STARTTLS |
| `SENTRY_MAIL_HOST` | `sentry.example.com` | FQDN that appears in "From" headers; needs to be set to send email at all |

### Secrets & cryptography

| Key | Default | Purpose |
| --- | --- | --- |
| `SENTRY_SECRET_KEY` | auto-generated by `install.sh` on first run | Django secret key. **Do not set or rotate** unless you're prepared to invalidate every DSN and session. Stored in `.self-hosted/.env`. |

### Health checks

Upstream-defined; override only if Docker is being weird:

| Key | Default | Purpose |
| --- | --- | --- |
| `HEALTHCHECK_INTERVAL` | `30s` | Between health probes for service containers |
| `HEALTHCHECK_TIMEOUT` | `1m30s` | Probe timeout |
| `HEALTHCHECK_RETRIES` | `10` | Consecutive failures before marking unhealthy |
| `HEALTHCHECK_START_PERIOD` | `10s` | Grace period at container start |
| `HEALTHCHECK_FILE_INTERVAL` | `60s` | Same, for file-based health checks (snuba consumers) |
| `HEALTHCHECK_FILE_TIMEOUT` | `10s` | … |
| `HEALTHCHECK_FILE_RETRIES` | `3` | … |
| `HEALTHCHECK_FILE_START_PERIOD` | `600s` | 10 minutes — first boot of consumers is slow |

### Database tuning

| Key | Default | Purpose |
| --- | --- | --- |
| `POSTGRES_MAX_CONNECTIONS` | `100` | Raising this increases CPU/RAM use of Postgres. See [getsentry/self-hosted#2740](https://github.com/getsentry/self-hosted/pull/2740). |

### Image pins (upstream-controlled)

All set in upstream's `.env` and pinned to `25.8.0` for this demo:

```
SENTRY_IMAGE=ghcr.io/getsentry/sentry:25.8.0
SNUBA_IMAGE=ghcr.io/getsentry/snuba:25.8.0
RELAY_IMAGE=ghcr.io/getsentry/relay:25.8.0
SYMBOLICATOR_IMAGE=ghcr.io/getsentry/symbolicator:25.8.0
TASKBROKER_IMAGE=ghcr.io/getsentry/taskbroker:25.8.0
VROOM_IMAGE=ghcr.io/getsentry/vroom:25.8.0
UPTIME_CHECKER_IMAGE=ghcr.io/getsentry/uptime-checker:25.8.0
```

To bump these in lockstep, override `SENTRY_VERSION` when running `setup.sh`:

```bash
SENTRY_VERSION=26.5.0 ./setup.sh
```

### Optional features

| Key | Default | Purpose |
| --- | --- | --- |
| `SETUP_JS_SDK_ASSETS` | unset (off) | Set to `1` to bundle JS SDK loader assets — only relevant if you'll instrument browser clients. |
| `DOCKER_PLATFORM` | unset | Force platform (`linux/amd64`) on M-series Macs if a service lacks an arm64 image. |

## Backend — `sentry-selfhost/.self-hosted/sentry/config.yml`

Deeper config (system URL prefix, beacon, mail backend choice). This file is
generated by `install.sh` on first run; subsequent edits survive re-runs.
**Not** managed by our wrapper. Edit directly inside `.self-hosted/` only if
you know you need a knob not exposed via `.env`.

Common edits:

| Key | Purpose |
| --- | --- |
| `system.url-prefix` | Public URL where Sentry is reachable (e.g. `https://sentry.example.com`). Used in notification emails and the SDK setup wizard. |
| `system.admin-email` | Receives Sentry's own internal alerts. |
| `system.secret-key` | Mirror of `SENTRY_SECRET_KEY`. Don't touch. |
| `mail.backend` | `smtp` to use the configured SMTP, `dummy` to silently drop mail. |

After edits: `cd .self-hosted && docker compose restart web worker`.

## Backend — `sentry-selfhost/docker-compose.override.yml`

Our local overlay. Owns:

- **Port mapping** — `web` container's port 9000 is published to
  `${SENTRY_BIND:-9000}` on the host.
- **Log rotation** — `json-file` driver with `max-size: 10m, max-file: 3` on
  `web`, `relay`, `worker`, `postgres`, `kafka`, `clickhouse`, `snuba-api`.

To add log rotation to a new service, reuse the YAML anchor:

```yaml
your-service:
  logging: *log-rotation
```

## Android — `android-app/local.properties`

Lives at `android-app/local.properties`. Not in git. Copy from
`local.properties.example`.

| Key | Default | Used by | Purpose |
| --- | --- | --- | --- |
| `sdk.dir` | (none — required) | Gradle | Absolute path to your local Android SDK |
| `sentry.dsn` | (none — required for events) | `BuildConfig.SENTRY_DSN` → `SentryAndroid.init` | DSN copied from Sentry → Settings → Projects → `<project>` → Client Keys |
| `sentry.environment` | `debug` | `BuildConfig.SENTRY_ENV` → `options.environment` | Surfaces in Sentry as the event environment dropdown |
| `sentry.userId` | `demo-user-001` | `BuildConfig.DEMO_USER_ID` → `SentryContextEnricher` | Becomes `event.user.id` on every event |

These flow into the build via `app/build.gradle.kts`:

```kotlin
buildConfigField("String", "SENTRY_DSN", "\"$sentryDsn\"")
buildConfigField("String", "SENTRY_ENV", "\"$sentryEnv\"")
buildConfigField("String", "DEMO_USER_ID", "\"$sentryUserId\"")
```

### DSN host matters

| Where you run the app | DSN host |
| --- | --- |
| Android emulator (AVD) on the same machine as Sentry | `10.0.2.2` |
| Physical device on the same Wi-Fi | LAN IP of the Sentry host |
| App on a developer laptop pointing at remote Sentry | Public hostname/IP |

The cleartext exception list in `app/src/main/res/xml/network_security_config.xml`
must include any host you use. Pre-allowed: `10.0.2.2`, `127.0.0.1`,
`localhost`, `192.168.0.0`, `192.168.1.0`.

## Android — Sentry SDK options

Set in `SentryDemoApplication.onCreate`:

```kotlin
SentryAndroid.init(this) { options ->
    options.dsn = BuildConfig.SENTRY_DSN
    options.environment = BuildConfig.SENTRY_ENV
    options.release = "${BuildConfig.APPLICATION_ID}@${BuildConfig.VERSION_NAME}"

    options.tracesSampleRate = 1.0
    options.profilesSampleRate = 1.0

    options.isAnrEnabled = true
    options.anrTimeoutIntervalMillis = 5_000L
    options.isAnrReportInDebug = true

    options.isAttachThreads = true
    options.isAttachScreenshot = false
    options.isAttachViewHierarchy = false

    options.isSendDefaultPii = true
    options.isEnableAutoActivityLifecycleTracing = true
    options.isEnableUserInteractionTracing = true
}
```

| Option | Demo value | Production guidance |
| --- | --- | --- |
| `tracesSampleRate` | `1.0` (100%) | `0.01`–`0.1` typical; sampling driven by traffic |
| `profilesSampleRate` | `1.0` | `0.01`–`0.1`; profiling is expensive |
| `isAnrEnabled` | `true` | `true` — always |
| `anrTimeoutIntervalMillis` | `5_000` | `5_000` is the OS-aligned default |
| `isAnrReportInDebug` | `true` | `false` for prod — devs are often paused in the debugger |
| `isAttachThreads` | `true` | `true` — context is invaluable |
| `isAttachScreenshot` | `false` | Set to `true` only with informed consent |
| `isAttachViewHierarchy` | `false` | Same — leaks UI text content |
| `isSendDefaultPii` | `true` | `false` for GDPR/HIPAA; lose IP and user agent |
| `isEnableAutoActivityLifecycleTracing` | `true` | Almost always `true` |
| `isEnableUserInteractionTracing` | `true` | Spammy if you have many touch events; consider `false` |

## Android — Sentry Gradle plugin

In `app/build.gradle.kts`:

```kotlin
sentry {
    autoUploadProguardMapping.set(false)
    includeProguardMapping.set(false)
    autoUploadNativeSymbols.set(false)
    tracingInstrumentation {
        enabled.set(true)
        features.set(setOf(
            InstrumentationFeature.DATABASE,
            InstrumentationFeature.FILE_IO,
            InstrumentationFeature.OKHTTP,
            InstrumentationFeature.COMPOSE,
        ))
    }
}
```

| Flag | Demo value | Production value |
| --- | --- | --- |
| `autoUploadProguardMapping` | `false` | `true` (release builds only) |
| `includeProguardMapping` | `false` | `true` |
| `autoUploadNativeSymbols` | `false` | `true` if you ship NDK code |
| `tracingInstrumentation.enabled` | `true` | `true` |

For mapping/symbol uploads, set `SENTRY_AUTH_TOKEN` in the build env. Optional:
`SENTRY_ORG`, `SENTRY_PROJECT` (otherwise set them in the plugin block).

KSP and Kotlin are joined-at-the-hip: bumping Kotlin requires a matching KSP
release. Check [KSP releases](https://github.com/google/ksp/releases) before
bumping.

## Ports & volumes summary

### Ports exposed by Sentry self-hosted

| Port | Service | Host | Purpose |
| --- | --- | --- | --- |
| `9000` | nginx | `${SENTRY_BIND:-9000}` | Web UI + ingestion API |
| internal | postgres `5432` | not exposed | DB access (use `docker compose exec postgres psql`) |
| internal | clickhouse `8123`, `9000`, `9009` | not exposed | OLAP DB |
| internal | kafka `9092` | not exposed | Event bus |
| internal | redis `6379` | not exposed | Cache + counters |
| internal | snuba-api `1218` | not exposed | OLAP query layer |

To expose Postgres / Clickhouse for ad-hoc queries, add a `ports:` entry under
that service in `docker-compose.override.yml`.

### Persistent volumes

| Volume | Mount | Service | Backup priority |
| --- | --- | --- | --- |
| `sentry-postgres` | `/var/lib/postgresql/data` | postgres | **high** — issues, projects, users |
| `sentry-clickhouse` | `/var/lib/clickhouse` | clickhouse | **high** — events, transactions |
| `sentry-data` | `/data` | web, worker | **high** — attachments, debug symbols |
| `sentry-kafka` | `/var/lib/kafka/data` | kafka | medium — replayable from upstream sources after a window |
| `sentry-zookeeper` | `/var/lib/zookeeper/data` | kafka | low — regenerable |
| `sentry-redis` | `/data` | redis | low — caches |
| `sentry-symbolicator` | `/data` | symbolicator | medium — debug symbol cache |
| `sentry-vroom-profiles` | `/var/vroom/sentry-profiles` | vroom | medium — profiling data |

Plus the most critical file:

| Path | What it is |
| --- | --- |
| `sentry-selfhost/.self-hosted/.env` | Holds `SENTRY_SECRET_KEY` and other generated secrets. **Lose this → every DSN is invalidated.** |

See [`operations.md`](./operations.md#backups) for the backup procedure.

## Build-time injection summary

```
local.properties           →  Gradle reads it  →  buildConfigField in
  sentry.dsn                                       BuildConfig.SENTRY_DSN
  sentry.environment                               BuildConfig.SENTRY_ENV
  sentry.userId                                    BuildConfig.DEMO_USER_ID

BuildConfig                →  SentryDemoApplication.onCreate
  SENTRY_DSN                   options.dsn
  SENTRY_ENV                   options.environment
  DEMO_USER_ID                 SentryContextEnricher.user.id
  APPLICATION_ID + VERSION_NAME  options.release
```

There are **no** runtime config files on the Android side — everything is
compiled in via `BuildConfig`. To change `sentry.dsn`, edit `local.properties`
and rebuild.
